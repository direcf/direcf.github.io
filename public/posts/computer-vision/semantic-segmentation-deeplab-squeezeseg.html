1. DeepLabV3 — Atrous Convolution

§01

Standard convolution downsamples spatial resolution to increase receptive field — essential for capturing context, but catastrophic for dense prediction tasks (you need per-pixel labels). DeepLab's key insight: atrous (dilated) convolution expands the receptive field by inserting zeros between kernel weights, without reducing resolution and without adding parameters.

For dilation rate r, a 3×3 kernel covers a (2r+1)×(2r+1) region but only touches 9 pixels. Formally, for a 1D signal: (F *ₐ k)[i] = Σⱼ F[i + r·j] · k[j]. At r=1 this is standard convolution; at r=6 the 3×3 kernel sees a 13×13 field.

  • DeepLabV1 / V2 — introduced atrous convolutions and Dense CRF post-processing to sharpen boundaries. CRF is slow (~1 second) and non-differentiable.
  • DeepLabV3 — removes Dense CRF entirely. Replaces it with ASPP (multi-scale atrous convolutions in parallel). Adds global average pooling branch for image-level context.
  • DeepLabV3+ — adds an encoder-decoder with skip connections from the backbone (inspired by U-Net). The decoder refines boundaries without needing CRF.

2. ASPP — Atrous Spatial Pyramid Pooling

§02
ASPP: five parallel branches at different atrous rates capture local detail (r=1) through large context (r=18) and global (avg pool), all concatenated

The global average pooling branch is crucial: it provides image-level context (what type of scene is this?), which cannot be captured by any finite atrous rate. After concatenation, a 1×1 conv reduces the channel dimension, and the result is bilinearly upsampled to the output resolution for final classification.

DeepLabV3+ adds a lightweight decoder: the 1/4-resolution low-level features from the backbone (before striding) are projected to 48 channels and concatenated with the upsampled ASPP output. Two 3×3 convolutions refine the merged feature, then bilinear upsample ×4 to full resolution. This U-Net-style skip gives sharper boundaries around thin objects (poles, cyclists) without a CRF.

3. SqueezeSegV2 — LiDAR Semantic Segmentation

§03

While DeepLabV3 targets RGB images, SqueezeSegV2 addresses a different modality: LiDAR point clouds for autonomous driving. The core idea: instead of processing the 3D point cloud with expensive 3D convolutions, project it onto a 2D range image (spherical projection) and apply a standard 2D CNN.

SqueezeSegV2 range image: LiDAR 3D scan → 2D spherical projection (azimuth × elevation × 5 channels). Standard 2D CNNs directly applicable.

4. SqueezeSegV2 Architecture & Domain Adaptation

§04

The encoder is a SqueezeNet-inspired network with Fire modules (squeeze + expand 1×1/3×3 convolutions). The decoder upsamples with transposed convolutions and adds a CRF-RNN layer for boundary refinement — similar in spirit to DeepLabV1's CRF but integrated into the network as a differentiable recurrent unit.

Domain adaptation is a critical concern: SqueezeSegV2 is trained on simulated data (CARLA / GTA) but must work on real LiDAR (KITTI). The simulation has perfect density and no sensor noise; real data has missing returns, rain droplets, and calibration imperfections. SqueezeSegV2 introduces Geodesic Correlation Alignment (GCA): minimise the difference between second-order statistics (correlation matrices) of simulated and real intermediate feature maps, measured along geodesic distances on the Riemannian manifold of positive-definite matrices. This adapts the encoder without needing labels from the real domain.

  • Speed — 8.7ms per full 360° LiDAR scan on a GTX 1080Ti. Nearly 10× faster than 3D voxel-based methods, making it suitable for real-time AV stacks.
  • Range image limitation — spherical projection loses some 3D structural information (two points at the same azimuth/elevation with different ranges collapse to one pixel). Occlusion handling is imperfect.
  • Context-Aware Feature Re-weighting (CAF) — added in V2; recalibrates channel responses based on global context (squeeze-and-excitation style), improving small object recall.

5. PyTorch Implementation — ASPP Module

§05
deeplabv3_aspp.py — Atrous Spatial Pyramid Pooling module
import torch
import torch.nn as nn
import torch.nn.functional as F


class AtrousConvBNReLU(nn.Module):
    def __init__(self, in_ch, out_ch, kernel_size, dilation=1, padding=0):
        super().__init__()
        self.block = nn.Sequential(
            nn.Conv2d(in_ch, out_ch, kernel_size,
                      padding=padding, dilation=dilation, bias=False),
            nn.BatchNorm2d(out_ch),
            nn.ReLU(inplace=True),
        )
    def forward(self, x):
        return self.block(x)


class ASPP(nn.Module):
    # Atrous Spatial Pyramid Pooling (DeepLabV3).
    # in_ch: backbone output channels (e.g. 2048 for ResNet-101)
    # out_ch: ASPP output channels (256 in paper)
    # rates: list of atrous rates for the parallel 3×3 branches

    def __init__(self, in_ch=2048, out_ch=256, rates=(6, 12, 18)):
        super().__init__()
        # Branch 1: 1×1 conv (r=1, no padding needed)
        self.b1 = AtrousConvBNReLU(in_ch, out_ch, 1)
        # Branches 2,3,4: 3×3 atrous convolutions
        self.branches = nn.ModuleList([
            AtrousConvBNReLU(in_ch, out_ch, 3, dilation=r, padding=r)
            for r in rates
        ])
        # Branch 5: global average pooling
        self.global_avg = nn.Sequential(
            nn.AdaptiveAvgPool2d(1),
            nn.Conv2d(in_ch, out_ch, 1, bias=False),
            nn.BatchNorm2d(out_ch),
            nn.ReLU(inplace=True),
        )
        # Fusion 1×1 conv
        num_branches = 1 + len(rates) + 1        # b1 + atrous + global
        self.project = nn.Sequential(
            nn.Conv2d(num_branches * out_ch, out_ch, 1, bias=False),
            nn.BatchNorm2d(out_ch),
            nn.ReLU(inplace=True),
            nn.Dropout(0.5),
        )

    def forward(self, x):
        H, W = x.shape[-2:]
        # Collect all branch outputs
        out = [self.b1(x)]
        for branch in self.branches:
            out.append(branch(x))
        # Global branch: pool → conv → upsample back to spatial size
        g = self.global_avg(x)
        g = F.interpolate(g, size=(H, W), mode='bilinear', align_corners=False)
        out.append(g)
        # Concatenate and project
        out = torch.cat(out, dim=1)              # B × (5×256) × H × W
        return self.project(out)                  # B × 256 × H × W


# Quick test
if __name__ == "__main__":
    aspp = ASPP(in_ch=2048, out_ch=256, rates=(6, 12, 18))
    x = torch.randn(2, 2048, 65, 65)            # typical ResNet-101 output
    out = aspp(x)
    print(out.shape)                             # torch.Size([2, 256, 65, 65])
    total = sum(p.numel() for p in aspp.parameters())
    print(f"ASPP params: {total:,}")             # ~16M

7. Commentary

§07

DeepLabV3's ASPP became a de facto standard in semantic segmentation. The ablation in the paper clearly shows each component earns its keep: removing the global average pooling branch costs ~1.5 mIoU; halving the number of atrous rates costs another ~1 mIoU. The encoder-decoder extension in V3+ addressed the remaining weakness (blurry boundaries) without reintroducing a CRF, making the architecture fully differentiable end-to-end.

The lineage from DeepLabV1 (atrous conv + CRF) → V2 (ASPP + CRF) → V3 (ASPP, no CRF) → V3+ (encoder-decoder) illustrates how architectural improvements can systematically replace post-processing heuristics.

SqueezeSegV2's range image idea lives on in modern LiDAR segmentation: RangeNet++, FIDNet, CENet all build on the spherical projection paradigm because it is fast and memory-efficient. The domain adaptation challenge (sim-to-real) remains an open problem, though self-supervised pretraining on real unlabelled scans has largely supplanted explicit alignment methods like GCA.

Together, these two papers bracket the 2D/3D segmentation divide: DeepLabV3 defines best practice for image-domain segmentation (which feeds into PointPainting), while SqueezeSegV2 shows that the same 2D CNN toolbox can be applied directly to LiDAR by choosing the right representation.
